🔄 ThreadLocal for Parallel Execution

public class BaseClass {
    
    protected static ThreadLocal<WebDriver> driver = new ThreadLocal<>();
    protected static ThreadLocal<ActionDriver> actionDriver = new ThreadLocal<>();
    
    @BeforeMethod
    public synchronized void setup() {
        // Initialize driver for current thread
        driver.set(new ChromeDriver());
        actionDriver.set(new ActionDriver(getDriver()));
    }
    
    public static WebDriver getDriver() {
        return driver.get();
    }
    
    public static ActionDriver getActionDriver() {
        return actionDriver.get();
    }
    
    @AfterMethod
    public synchronized void tearDown() {
        if(getDriver() != null) {
            getDriver().quit();
        }
        driver.remove();
        actionDriver.remove();
    }
}

🔁 Retry Analyzer

import org.testng.IRetryAnalyzer;
import org.testng.ITestResult;

public class RetryAnalyzer implements IRetryAnalyzer {
    
    private int retryCount = 0;
    private static final int maxRetryCount = 2;
    
    @Override
    public boolean retry(ITestResult result) {
        if(retryCount < maxRetryCount) {
            retryCount++;
            return true;
        }
        return false;
    }
}

// Use in test
@Test(retryAnalyzer = RetryAnalyzer.class)
public void testLogin() { }

✅ Framework Best Practices

  • Follow Page Object Model design pattern
  • Use configuration files for environment settings
  • Implement ActionDriver for reusable actions
  • Use ThreadLocal for parallel execution safety
  • Integrate logging and reporting
  • Implement retry mechanism for flaky tests
  • Use data-driven approach with Excel/DataProviders
  • Handle exceptions gracefully
  • Take screenshots on failures
  • Use meaningful test and method names
  • Keep code DRY (Don't Repeat Yourself)
  • Version control with Git
  • CI/CD integration ready

📊 Design Patterns Used

  • Page Object Model: Encapsulate page elements and actions
  • Singleton Pattern: ExtentManager, LoggerManager
  • Factory Pattern: Browser initialization
  • Strategy Pattern: Different wait strategies
  • Observer Pattern: TestNG Listeners

📝 Summary

A well-architected framework follows design patterns, uses proper separation of concerns, supports parallel execution, and integrates reporting and logging for comprehensive test automation.
