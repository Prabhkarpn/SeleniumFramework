🎯 What are Locators?

Locators are the way to identify and interact with web elements on a webpage. They act as addresses that tell Selenium which element to perform actions on. Choosing the right locator strategy is crucial for creating reliable and maintainable test automation scripts.

🔑 Why Locators are Important

  • Element Identification: Uniquely identify elements on the page
  • Test Reliability: Good locators make tests less brittle
  • Maintenance: Easy-to-understand locators simplify updates
  • Performance: Efficient locators improve test execution speed

1️⃣ ID Locator

The ID attribute is the most preferred locator as it's unique and fast. HTML IDs should be unique on a page.

HTML:
<input type="text" id="username" name="user"> 
// Locate by ID
WebElement usernameField = driver.findElement(By.id("username"));
usernameField.sendKeys("admin");

✅ Advantages:

  • Fastest locator strategy
  • Most reliable (IDs should be unique)
  • Easy to read and maintain

❌ Limitations:

  • Not all elements have IDs
  • Dynamic IDs may change on each page load

2️⃣ Name Locator

The Name attribute is commonly used in form elements.

HTML:
<input type="password" name="password"> 
// Locate by Name
WebElement passwordField = driver.findElement(By.name("password"));
passwordField.sendKeys("admin123");

3️⃣ Class Name Locator

Locates elements by their CSS class name. Note: Multiple elements can share the same class.

HTML:
<button class="btn-submit primary">Submit</button> 
// Locate by Class Name (use single class only)
WebElement submitButton = driver.findElement(By.className("btn-submit"));

⚠️ Important: When using By.className(), you can only specify ONE class name, not multiple classes separated by spaces.

4️⃣ Tag Name Locator

Locates elements by their HTML tag name. Useful when you want all elements of a certain type.

// Find all links on the page
List<WebElement> allLinks = driver.findElements(By.tagName("a"));
System.out.println("Total links: " + allLinks.size());

// Find all input fields
List<WebElement> allInputs = driver.findElements(By.tagName("input"));

5️⃣ Link Text Locator

Specifically for anchor tags (<a>). Finds links by their exact visible text.

HTML:
<a href="/login">Click Here to Login</a> 
// Locate by exact link text
WebElement loginLink = driver.findElement(By.linkText("Click Here to Login"));
loginLink.click();

6️⃣ Partial Link Text Locator

Similar to Link Text, but matches partial text in links.

// Locate by partial link text
WebElement loginLink = driver.findElement(By.partialLinkText("Login"));
loginLink.click();

7️⃣ CSS Selector

CSS Selectors are powerful and fast. They use CSS syntax to locate elements.

CSS Selector Examples:

// By ID
driver.findElement(By.cssSelector("#username"));

// By Class
driver.findElement(By.cssSelector(".btn-submit"));

// By Attribute
driver.findElement(By.cssSelector("input[name='email']"));

// Tag with class
driver.findElement(By.cssSelector("button.btn-primary"));

// Multiple classes
driver.findElement(By.cssSelector(".btn.btn-primary.active"));

// Contains attribute value
driver.findElement(By.cssSelector("input[id*='user']"));

// Starts with
driver.findElement(By.cssSelector("input[id^='txt']"));

// Ends with
driver.findElement(By.cssSelector("input[id$='name']"));

// Direct child
driver.findElement(By.cssSelector("div.form-group > input"));

// nth-child
driver.findElement(By.cssSelector("ul li:nth-child(2)"));

8️⃣ XPath

XPath is the most powerful and flexible locator strategy. It can traverse both forward and backward in the DOM.

Types of XPath:

A. Absolute XPath (Not Recommended)

Starts from the root and traverses through every node. Brittle and breaks easily.

// Absolute XPath - Avoid this!
/html/body/div[1]/div[2]/form/input[1]

B. Relative XPath (Recommended)

Starts from any node and searches in the DOM tree. More flexible and reliable.

// Relative XPath - Use this!
//input[@id='username']
//button[text()='Login']

XPath Syntax Guide:

SyntaxExampleDescription
//tag[@attribute='value']//input[@id='email']Basic XPath
//tag[text()='value']//button[text()='Submit']By text content
//tag[contains(@attr,'value')]//input[contains(@id,'user')]Contains
//tag[starts-with(@attr,'value')]//input[starts-with(@id,'txt')]Starts with

//label[@for='username']/following-sibling::input

// Preceding sibling
//input[@id='password']/preceding-sibling::label

// Following

// Multiple attributes

// Not condition
//input[@type='text' and not(@disabled)]

🆕 Selenium 4: Relative Locators

Selenium 4 introduced Relative Locators (Friendly Locators) that allow you to find elements based on their position relative to other elements.

Relative Locator Methods:

  • above() - Element above the specified element
  • below() - Element below the specified element
  • toLeftOf() - Element to the left
  • toRightOf() - Element to the right
  • near() - Element within 50 pixels
import static org.openqa.selenium.support.locators.RelativeLocator.with;

// Find element above another element
WebElement passwordField = driver.findElement(By.id("password"));
WebElement usernameField = driver.findElement(
    with(By.tagName("input")).above(passwordField)
);

// Find element below
WebElement submitButton = driver.findElement(
    with(By.tagName("button")).below(passwordField)
);

// Find element to the right
WebElement cancelButton = driver.findElement(
    with(By.tagName("button")).toRightOf(submitButton)
);

// Find element near (within 50 pixels)
WebElement label = driver.findElement(
    with(By.tagName("label")).near(usernameField)
);

// Chain multiple conditions
WebElement element = driver.findElement(
    with(By.tagName("button"))
        .below(usernameField)
        .toRightOf(passwordField)
);

🎯 Locator Strategy Selection Guide

Priority Order (Best to Least):

  1. ID: If element has unique ID
  2. Name: For form elements with unique names
  3. CSS Selector: Fast and flexible
  4. XPath: When CSS can't solve the problem
  5. Link Text: For links with unique text
  6. Class Name: When class is unique
  7. Tag Name: For finding multiple elements

🔍 Finding Multiple Elements

// findElements() returns List<WebElement>
List<WebElement> allLinks = driver.findElements(By.tagName("a"));
System.out.println("Total links: " + allLinks.size());

// Iterate through elements
for(WebElement link : allLinks) {
    System.out.println("Link text: " + link.getText());
    System.out.println("Link URL: " + link.getAttribute("href"));
}

// Find all elements with specific class
List<WebElement> buttons = driver.findElements(By.className("btn"));

// XPath for multiple elements
List<WebElement> checkboxes = 
    driver.findElements(By.xpath("//input[@type='checkbox']"));

🛠️ Browser Developer Tools for Locators

Chrome DevTools:

  1. Right-click on element → Inspect
  2. In Elements tab, right-click on HTML → Copy → Copy XPath/CSS Selector
  3. Use Console: $x("xpath") or $$("css")

Testing Locators in Console:

// Test XPath in console
$x("//input[@id='username']")

// Test CSS Selector in console
$$("input#username")

// Count matching elements
$x("//a").length
$$("a").length

✅ Best Practices

  1. Prefer ID when available: Most reliable and fastest
  2. Use CSS over XPath when possible: Better performance
  3. Avoid absolute XPath: Very brittle
  4. Create readable locators: Makes maintenance easier
  5. Use unique attributes: id, name, data-testid
  6. Avoid using indexes: [1], [2] can break easily
  7. Test locators in browser console: Verify before coding
  8. Use contains() for dynamic IDs: Handle changing parts
  9. Document complex locators: Add comments explaining logic
  10. Work with developers: Request test-specific attributes

❌ Common Mistakes to Avoid

  • Using generated absolute XPath: Breaks with UI changes
  • Multiple class names in className(): Use CSS instead
  • Not verifying locator uniqueness: May select wrong element
  • Hardcoding indexes without validation: Fragile locators
  • Ignoring dynamic content: IDs/classes may change
  • Over-complicated locators: Hard to maintain

📝 Summary

In this module, we explored all 8 locator strategies in Selenium, learned XPath and CSS Selector syntax, and discovered Selenium 4's relative locators. Choosing the right locator is crucial for building reliable and maintainable test automation.

Key Takeaways:

  • ID is the fastest and most reliable locator when available
  • CSS Selectors are faster than XPath for most scenarios
  • XPath provides more power and flexibility (parent traversal, text matching)
  • Relative Locators in Selenium 4 simplify location based on element positions
  • Always test locators in browser console before implementation
  • Avoid absolute XPath and prefer relative XPath with unique attributes
