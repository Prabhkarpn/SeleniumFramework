🎯 Why Waits are Important

Modern web applications use AJAX, JavaScript, and dynamic content loading. Elements may not be immediately available when the page loads. Waits help synchronize your test scripts with the application state, making tests more reliable and stable.

📋 Types of Waits

Wait TypeScopeUse Case
Implicit WaitGlobalDefault wait for all elements
Explicit WaitSpecificWait for specific conditions
Fluent WaitSpecificCustom polling and ignore exceptions
Thread.sleep()N/A❌ Not recommended

1️⃣ Implicit Wait

Implicit wait tells WebDriver to poll the DOM for a certain amount of time when trying to find any element.

import java.time.Duration;

// Set implicit wait (applies to all findElement calls)
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// Now all findElement calls will wait up to 10 seconds
WebElement element = driver.findElement(By.id("dynamic-element"));

✅ Advantages:

  • Easy to implement - single line of code
  • Applies globally to all findElement() calls
  • No need to specify wait for each element

❌ Disadvantages:

  • Not flexible - same timeout for all elements
  • Can slow down tests if set too high
  • Cannot wait for specific conditions

2️⃣ Explicit Wait

Explicit wait allows you to wait for a specific condition on a specific element.

import org.openqa.selenium.support.ui.WebDriverWait;
import org.openqa.selenium.support.ui.ExpectedConditions;
import java.time.Duration;

// Create WebDriverWait object
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(20));

// Wait for element to be visible
WebElement element = wait.until(
    ExpectedConditions.visibilityOfElementLocated(By.id("dynamic-element"))
);

// Wait for element to be clickable
wait.until(ExpectedConditions.elementToBeClickable(By.id("submit-btn"))).click();

// Wait for text to be present
wait.until(ExpectedConditions.textToBePresentInElementLocated(
    By.id("message"), "Success"
));

Common ExpectedConditions:

// Element visibility
wait.until(ExpectedConditions.visibilityOfElementLocated(locator));
wait.until(ExpectedConditions.visibilityOf(element));

// Element clickable
wait.until(ExpectedConditions.elementToBeClickable(locator));

// Element presence in DOM
wait.until(ExpectedConditions.presenceOfElementLocated(locator));

// Element invisibility
wait.until(ExpectedConditions.invisibilityOfElementLocated(locator));

// Text conditions
wait.until(ExpectedConditions.textToBe(locator, "Expected Text"));
wait.until(ExpectedConditions.textToBePresentInElementLocated(locator, "text"));

// URL conditions
wait.until(ExpectedConditions.urlToBe("https://example.com"));
wait.until(ExpectedConditions.urlContains("login"));

// Title conditions
wait.until(ExpectedConditions.titleIs("Page Title"));
wait.until(ExpectedConditions.titleContains("Title"));

// Alert conditions
wait.until(ExpectedConditions.alertIsPresent());

// Frame availability
wait.until(ExpectedConditions.frameToBeAvailableAndSwitchToIt("frameName"));

// Element selection state
wait.until(ExpectedConditions.elementToBeSelected(locator));

// Attribute conditions
wait.until(ExpectedConditions.attributeToBe(locator, "class", "active"));
wait.until(ExpectedConditions.attributeContains(locator, "class", "btn"));

// Number of windows
wait.until(ExpectedConditions.numberOfWindowsToBe(2));

// Staleness of element
wait.until(ExpectedConditions.stalenessOf(element));

3️⃣ Fluent Wait

Fluent wait is similar to explicit wait but provides more control over polling frequency and exception handling.

import org.openqa.selenium.support.ui.FluentWait;
import org.openqa.selenium.support.ui.Wait;
import org.openqa.selenium.NoSuchElementException;

// Create FluentWait
Wait fluentWait = new FluentWait(driver)
    .withTimeout(Duration.ofSeconds(30))           // Maximum wait time
    .pollingEvery(Duration.ofSeconds(2))           // Check every 2 seconds
    .ignoring(NoSuchElementException.class);       // Ignore this exception

// Use the wait
WebElement element = fluentWait.until(driver -> {
    return driver.findElement(By.id("dynamic-element"));
});

// With custom condition
WebElement searchBtn = fluentWait.until(driver -> {
    WebElement el = driver.findElement(By.id("search-btn"));
    return el.isDisplayed() ? el : null;
});

4️⃣ Custom Wait Conditions

// Custom wait for element to have specific text
public static ExpectedCondition textToBeInElement(
    final WebElement element, final String text) {
    return new ExpectedCondition() {
        public Boolean apply(WebDriver driver) {
            return element.getText().contains(text);
        }
    };
}

// Usage
wait.until(textToBeInElement(element, "Expected Text"));

// Wait for page to load completely
public static ExpectedCondition pageLoadComplete() {
    return new ExpectedCondition() {
        public Boolean apply(WebDriver driver) {
            JavascriptExecutor js = (JavascriptExecutor) driver;
            return js.executeScript("return document.readyState")
                .toString().equals("complete");
        }
    };
}

wait.until(pageLoadComplete());

⚡ Wait Implementation in Framework

public class ActionDriver {
    private WebDriver driver;
    private WebDriverWait wait;
    
    public ActionDriver(WebDriver driver) {
        this.driver = driver;
        int explicitWait = Integer.parseInt(
            BaseClass.getProp().getProperty("explicitWait")
        );
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(explicitWait));
    }
    
    private void waitForElementToBeClickable(By locator) {
        wait.until(ExpectedConditions.elementToBeClickable(locator));
    }
    
    private void waitForElementToBeVisible(By locator) {
        wait.until(ExpectedConditions.visibilityOfElementLocated(locator));
    }
    
    public void click(By locator) {
        waitForElementToBeClickable(locator);
        driver.findElement(locator).click();
    }
    
    public void enterText(By locator, String text) {
        waitForElementToBeVisible(locator);
        WebElement element = driver.findElement(locator);
        element.clear();
        element.sendKeys(text);
    }
}

✅ Best Practices

  • Use Explicit Wait over Implicit Wait for better control
  • Set implicit wait once in BaseClass setup method
  • Don't mix implicit and explicit waits (can cause unpredictable behavior)
  • Use appropriate ExpectedConditions for your scenario
  • Create reusable wait methods in utility classes
  • Avoid Thread.sleep() - it's inflexible and slows tests
  • Use FluentWait for custom polling requirements
  • Handle TimeoutException with proper error messages

📝 Summary

Waits are essential for handling timing issues in modern web applications. Explicit waits provide the most flexibility, while implicit waits offer simplicity. Choose the right wait strategy based on your testing needs.
