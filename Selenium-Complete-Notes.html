1. What is Software Testing?

Imagine you bought a brand new mobile phone. Before you start using it daily, what do you do? You check it — does the camera work? Does the speaker work? Can you make a call? You are testing the phone before relying on it.

Software Testing is exactly the same idea, but for software (websites, mobile apps, APIs). It's the process of checking whether the software does what it's supposed to do, and does not do what it's not supposed to do.

Real-life analogy Think of a chef in a restaurant. Before serving a dish to customers, the chef tastes it — is the salt right? Is it cooked properly? Is the temperature good? If the chef serves a bad dish, the restaurant loses customers. Similarly, if a company releases buggy software, it loses users and money. Testers are the "chefs who taste the dish before customers eat it."

Why is Testing Important?

  • Money: A bug in a payment website can charge users twice. That's lost money and lost trust.
  • Reputation: If your shopping app crashes during the Diwali sale, customers will switch to a competitor.
  • Safety: Some software runs hospitals, flights, cars. A bug there can cost lives.
  • Compliance: Banks, insurance, healthcare must pass strict quality checks by law.
Famous real-world bugs
  • Ariane 5 rocket (1996) — exploded 37 seconds after launch due to a software bug. Cost: ~$370 million.
  • Knight Capital (2012) — bad software deployed to trading servers lost $440 million in 45 minutes.
  • Daily examples: an e-commerce site shows price as zero, a banking app sends OTP to wrong number, a video call drops every 2 minutes.

Types of Testing (the big picture)

TypeWhat it checksSimple example
FunctionalDoes the feature work?Does "Login" button log me in?
UIDoes it look right?Is the logo visible? Are buttons aligned?
PerformanceIs it fast enough?Does the homepage load in under 3 seconds with 1000 users?
SecurityIs it safe?Can a hacker steal my password?
CompatibilityDoes it work everywhere?Does it work on Chrome, Edge, Firefox, mobile?
RegressionDid the new change break old features?After adding "Forgot Password", does normal login still work?
Selenium fits where? Selenium is mainly for Functional, UI, Compatibility, and Regression testing of web applications. It cannot test mobile apps directly (use Appium), it cannot do load testing (use JMeter), and it cannot test APIs alone (use Rest Assured / Postman).

Who does testing?

  • Developer — tests their own code (unit tests).
  • Manual QA Tester — clicks through the app like a real user, finds bugs.
  • Automation QA / SDET — writes code that simulates a user. This is what we are learning.
  • End User — the final test (UAT — User Acceptance Testing).

2. Manual vs Automation Testing

Let me explain with a story. Imagine your manager asks you to verify that a website's login works correctly — with valid credentials, invalid credentials, empty username, empty password, special characters, very long username, etc. That's about 20 cases.

You can do this two ways:

Manual Testing

Open Chrome, type the URL, type username, type password, click login, see the result, write it down. Repeat 20 times. Tomorrow, the developer fixes a bug, you do it all over again. Every release. Every browser. Forever.

Automation Testing

You write a small program once. The program opens Chrome, types username, types password, clicks login, checks the result, and reports pass/fail. Tomorrow, you click "Run" and the program does it again in 10 seconds. On Edge too. On Firefox too.

Real-life analogy Manual = washing dishes by hand. Works fine if you have 5 plates. But if you have 500 plates every day, you'll be exhausted and slow. Automation = a dishwasher. You spend time setting it up, but once it works, it cleans 500 plates while you have lunch.

When to automate vs when not to?

Good candidates for automationBetter to do manually
Repetitive tests run every release (regression)One-time exploratory testing
Stable features that don't change oftenFeatures that change every week
Tests that need to run on multiple browsersUI look-and-feel checks (humans see better)
Performance-style smoke testsUsability / "does it feel nice?" testing

Pros & Cons

  • Automation Pros: Fast, repeatable, runs at night, consistent (no human typo), can simulate thousands of users (with right tools).
  • Automation Cons: Initial cost (you must write code), maintenance (when UI changes, scripts break), cannot judge "looks ugly", needs technical skills.
Important misconception Automation is not a replacement for manual testing. It's a partner. A good QA team uses both. Automation handles the boring repeated stuff, humans handle exploration, creativity, and judgment.

3. What is Selenium?

In one line: Selenium is a free, open-source tool that lets you control a web browser using code.

That's it. When you write Selenium code, your program does what you would normally do with your hand and mouse: open a browser, type a URL, click a button, fill a form, read text, take a screenshot.

Real-life analogy Imagine you have a robot hand sitting next to your computer. You give it instructions in English: "Open Chrome, go to gmail.com, type my email, type my password, click Sign In." The robot does it. Selenium is exactly that — a robot hand for the browser, but you give instructions in code (Java, Python, etc.).

Why Selenium became popular

  • Free — no license cost (vs. paid tools like UFT/QTP that cost lakhs).
  • Open source — huge community, tons of help on Stack Overflow.
  • Multiple languages — Java, Python, C#, JavaScript, Ruby, Kotlin.
  • Multiple browsers — Chrome, Firefox, Edge, Safari, Opera.
  • Multiple OS — Windows, Mac, Linux.
  • Integrates with everything — TestNG, JUnit, Maven, Jenkins, Docker, GitHub Actions, ExtentReports, log4j…

The Selenium Family

Selenium is not one tool. It's a family of tools. You will mostly use Selenium WebDriver in your career, but it helps to know all four.

ComponentWhat it doesBeginner analogy
Selenium IDE A browser plugin (Chrome/Firefox). You record your clicks, it generates a test you can replay. No coding needed. Like a tape recorder — record once, replay forever. Good for demos, weak for real projects.
Selenium RC (Remote Control) The old version (deprecated). Used a "server" to control browsers via JavaScript injection. Like an old Nokia phone — once popular, now retired. Don't worry about it.
Selenium WebDriver The main hero. A library you import in your code. Talks directly to the browser using its native automation API. Like a smartphone — modern, powerful, what we use today.
Selenium Grid Lets you run tests in parallel on multiple machines / browsers. Like a call-center with many agents — instead of 1 test at a time, run 100 in parallel.

How Selenium WebDriver works (under the hood)

Your Java Code (e.g. driver.findElement().click()) | v +-------------------+ HTTP (JSON) +------------------+ Native +-------------+ | Selenium Java | ----------------> | Browser Driver | ------------> | Real Browser| | Client Library | "click element" | (e.g. ChromeDr.) | automation | (Chrome) | +-------------------+ <---------------- +------------------+ <------------ +-------------+ response (json)
  1. You write code: driver.findElement(By.id("login")).click();
  2. The Selenium client library converts that into an HTTP request (a small JSON message).
  3. That request is sent to a Browser Driver — a small executable like chromedriver.exe.
  4. The driver speaks the browser's native automation language and tells the browser to click.
  5. The browser responds, the driver sends the response back, your code continues.
Good news From Selenium 4.6+, you don't need to download chromedriver/edgedriver/geckodriver manually anymore. Selenium ships with Selenium Manager which downloads the right driver automatically. (Your repo uses selenium-java 4.28.1 — you're on the modern stack.)

What Selenium can do

  • Open/close browsers, navigate URLs, refresh, back, forward.
  • Find any element on a web page (button, input, link).
  • Click, type, select dropdown, drag-and-drop, hover, right-click.
  • Read text, attribute values, CSS properties.
  • Handle alerts, popups, frames, multiple browser tabs.
  • Take screenshots, execute JavaScript, manage cookies.

What Selenium cannot do

  • Cannot test desktop apps (use WinAppDriver, Pywinauto).
  • Cannot test mobile apps (use Appium).
  • Cannot read CAPTCHA / OTP / barcodes.
  • Cannot do performance / load testing on its own (use JMeter, Gatling).
  • Cannot test bitmap content like videos, games rendered on canvas.
Interview question Q: What is the difference between Selenium and QTP/UFT?
Selenium is free, open-source, supports many languages and many browsers, but only does web. QTP/UFT (now MicroFocus UFT One) is paid, supports VBScript only, and can do desktop + web + some mobile. Industry has largely shifted to Selenium for cost and flexibility.

4. Java Essentials You Need for Selenium

You don't need to be a Java master to do Selenium. But you must be comfortable with about 10 core ideas. Let's go through them quickly.

Real-life analogy Java is just a language — like English. To order food at a restaurant, you don't need to know Shakespeare's English; you just need 200 useful words. Similarly, for Selenium you don't need all of Java — just the basics below.

4.1 Variables & Data Types

A variable is a named box that holds a value. The data type tells what kind of value goes in the box.

String name = "Prabhakar";     // text
int age = 28;                      // whole number
double salary = 45000.50;          // decimal number
boolean isLoggedIn = true;       // true/false
char grade = 'A';                  // single character

4.2 Operators

  • Arithmetic: +   -   *   /   %
  • Comparison: ==   !=   >   <   >=   <=
  • Logical: && (AND)   || (OR)   ! (NOT)

4.3 Conditional Statements (if / else)

if (age >= 18) {
    System.out.println("Allowed");
} else {
    System.out.println("Not allowed");
}

4.4 Loops

Loops repeat actions. Used a lot in Selenium — e.g., "loop through all rows of a table".

// for loop — when you know how many times
for (int i = 1; i <= 5; i++) {
    System.out.println("Row " + i);
}

// while loop — when you don't know how many times
while (!loginButton.isDisplayed()) {
    Thread.sleep(500);
}

4.5 Arrays & Collections

An array / list stores many values together. Selenium often returns lists of elements.

// Array (fixed size)
String[] browsers = {"chrome", "edge", "firefox"};

// ArrayList (grows dynamically) - more common
List<String> users = new ArrayList<>();
users.add("alice");
users.add("bob");

4.6 Methods (Functions)

A method is a reusable block of code. Give it a name, call it whenever you need.

public void login(String user, String pass) {
    driver.findElement(By.name("username")).sendKeys(user);
    driver.findElement(By.name("password")).sendKeys(pass);
    driver.findElement(By.xpath("//button[@type='submit']")).click();
}

// Call it
login("Admin", "admin123");

4.7 Classes & Objects (OOP)

A class is a blueprint. An object is the actual thing made from the blueprint.

Real-life analogy A "Car" class is the blueprint with attributes (color, brand, speed) and behaviors (start, stop, accelerate). When you actually buy "my red Honda" and "your white Toyota", those are objects made from the Car blueprint. 
public class Car {
    String color;
    String brand;

    public void start() {
        System.out.println(brand + " started");
    }
}

// Create an object (instance) of the class
Car myCar = new Car();
myCar.brand = "Honda";
myCar.start();    // Honda started

4.8 The 4 Pillars of OOP (in 1 line each)

  • Encapsulation — hide variables, expose only methods. (Use private + getters/setters.)
  • Inheritance — one class reuses another (class HomePageTest extends BaseClass).
  • Polymorphism — same method name, different behavior (WebDriver driver = new ChromeDriver();).
  • Abstraction — show only what's needed, hide complexity (interface WebDriver hides browser internals).
Where you'll see this in your framework Your BaseClass.java is the parent. Your test classes like LoginPageTest use extends BaseClass — that's Inheritance. Your locators in LoginPage are private — that's Encapsulation. The line WebDriver driver = new ChromeDriver(); — that's Polymorphism (interface holding implementation reference).

4.9 Exception Handling (try-catch)

Sometimes code fails — element not found, network error, etc. We catch the failure so the program doesn't crash.

try {
    driver.findElement(By.id("login")).click();
} catch (Exception e) {
    System.out.println("Login button missing: " + e.getMessage());
}

4.10 String Operations

String s = "Hello World";
s.length();          // 11
s.toUpperCase();     // "HELLO WORLD"
s.contains("World"); // true
s.equals("hello");   // false (case-sensitive)
s.equalsIgnoreCase("HELLO WORLD"); // true
s.trim();            // removes spaces from both ends
s.split(" ");        // {"Hello","World"}
Interview question Q: Difference between == and .equals() in Java?
== compares memory addresses. .equals() compares actual content. For Strings always use .equals() or .equalsIgnoreCase().

6. Your First Selenium Test

Let's write the simplest possible Selenium test together, then break down every line.

package com.demo;

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class FirstTest {
    public static void main(String[] args) throws InterruptedException {

        // 1. Create a browser session
        WebDriver driver = new ChromeDriver();

        // 2. Maximize the window
        driver.manage().window().maximize();

        // 3. Navigate to URL
        driver.get("https://opensource-demo.orangehrmlive.com");

        // 4. Find username field, type
        driver.findElement(By.name("username")).sendKeys("Admin");

        // 5. Find password field, type
        driver.findElement(By.name("password")).sendKeys("admin123");

        // 6. Click the login button
        driver.findElement(By.xpath("//button[@type='submit']")).click();

        // 7. Pause to see result (bad practice but ok for first test)
        Thread.sleep(3000);

        // 8. Print the page title
        System.out.println("Title: " + driver.getTitle());

        // 9. Close everything
        driver.quit();
    }
}

Line-by-line explanation

  • WebDriver driver = new ChromeDriver(); — Open a new Chrome window controlled by code.
  • driver.manage().window().maximize(); — Maximize so all elements are visible.
  • driver.get(url); — Navigate to a URL (like typing in the address bar).
  • driver.findElement(By.name("...")); — Find a single element using a "locator". The locator says "find the element whose name attribute is X".
  • .sendKeys("Admin"); — Type text into the found element.
  • .click(); — Click the found element.
  • Thread.sleep(3000); — Pause 3 seconds. (We'll replace this with proper waits later.)
  • driver.getTitle(); — Read the browser tab title.
  • driver.quit(); — Close the browser AND end the WebDriver session.
close() vs quit() driver.close() closes the current tab/window only. driver.quit() closes all windows AND ends the WebDriver session (releases memory, kills the chromedriver.exe process). Always use quit() at end of test.

7. HTML & DOM Basics (5 minutes)

To find elements on a web page, you must understand how a web page is built. Don't worry — you don't need to be a web developer.

Every web page is written in HTML. HTML is a tree of tags. Each tag has attributes.

<html>
  <body>
    <h1 id="title">Welcome</h1>
    <input name="username" type="text" />
    <input name="password" type="password" />
    <button type="submit" class="btn-primary">Login</button>
  </body>
</html>
  • Tag — the type of element: <h1>, <input>, <button>, <a>, <div>.
  • Attribute — extra info: id, name, class, type, href, placeholder.
  • Text — visible content between tags: "Welcome", "Login".

The DOM (Document Object Model) is the browser's internal representation of HTML — a tree structure. When Selenium "finds an element", it walks the DOM tree.

How to inspect elements (essential skill!)

  1. Open Chrome on any web page.
  2. Right-click on the element you want → Inspect.
  3. DevTools opens. The selected HTML is highlighted.
  4. Read the tag name & attributes (id, name, class, etc.) — these are your locators.
Pro tips for DevTools
  • Press Ctrl+F in the Elements panel to test XPath/CSS selectors live.
  • Right-click element → Copy → Copy XPath (but prefer hand-written XPath — copied ones break easily).
  • Press F12 to open/close DevTools. Press Ctrl+Shift+C to enter "pick" mode.

8. Locators — Finding Elements (Most Important Topic!)

Real-life analogy Imagine your friend asks you to deliver a parcel to "John in Mumbai". That's vague — there are many Johns. But if she says "John, House #42, 3rd Cross, MG Road, Mumbai" — now you can find him exactly. Locators are the address of an element on a web page.

Selenium provides 8 types of locators. Let's see all of them.

#LocatorExample syntaxWhen to use
1idBy.id("login")Best, fastest. Use first if available.
2nameBy.name("username")2nd best, very fast.
3classNameBy.className("btn-primary")Single class only (no spaces).
4tagNameBy.tagName("input")For groups: count all inputs, links.
5linkTextBy.linkText("Logout")Only for <a> tags — exact match.
6partialLinkTextBy.partialLinkText("Log")For <a> tags — partial match.
7cssSelectorBy.cssSelector("input#login")Powerful & fast. Recommended.
8xpathBy.xpath("//button[@type='submit']")Most powerful. Can go up the DOM. Slower.

Priority order (industry best practice)

  1. id (if unique) — #1 choice
  2. name — #2 choice
  3. cssSelector — preferred for complex cases
  4. xpath — last resort, but most flexible
  5. Avoid className (often not unique) and tagName (almost never unique alone).

Examples on the OrangeHRM login page (your repo!)

// HTML on OrangeHRM login page (simplified):
// <input name="username" placeholder="Username" />
// <input name="password" type="password" placeholder="Password" />
// <button type="submit">Login</button>

findElement vs findElements

  • findElement(...) — returns the first matching element. Throws error if none found.
  • findElements(...) — returns a list of all matches. Returns empty list if none (no error).
// Count how many links on a page
List<WebElement> allLinks = driver.findElements(By.tagName("a"));
System.out.println("Total links: " + allLinks.size());

// Loop through all rows of a table
List<WebElement> rows = driver.findElements(By.xpath("//table//tr"));
for (WebElement row : rows) {
    System.out.println(row.getText());
}
Interview question Q: What if findElement doesn't find the element?
It throws NoSuchElementException. With findElements, it returns an empty list — no exception. So findElements(...).size() == 0 is a clean way to check existence.

9. XPath & CSS Selectors (Deep Dive)

This is the chapter most students struggle with. Let's go slow.

9.1 What is XPath?

XPath = XML Path Language. It's a query language to navigate an HTML/XML document. Imagine you have a tree, and you want to point at one leaf — XPath is the "path from root to that leaf".

Real-life analogy XPath is like Google Maps directions: "From your home, go straight, take 2nd left, find the 3rd house on the right." Each step navigates the tree.

9.2 Two types of XPath

TypeStarts withExampleNotes
Absolute XPath/ (single slash)/html/body/div[1]/form/input[1]Full path from root. Avoid — breaks if any parent changes.
Relative XPath// (double slash)//input[@name='username']Searches anywhere. Recommended.

9.3 XPath syntax (the formula)

// Format:
// //tag[@attribute='value']

// Examples:
//input[@name='username']
//button[@type='submit']
//a[@href='/logout']
//p[text()='Invalid credentials']     // match by visible text
//*[@id='loginBtn']                    // * means any tag

9.4 XPath functions (very useful!)

FunctionWhat it doesExample
contains()Partial match//input[contains(@name,'user')]
starts-with()Match prefix//input[starts-with(@id,'btn-')]
text()Match by visible text//button[text()='Login']
not()Negate//input[not(@disabled)]

9.5 XPath axes (going up, down, sideways)

The killer feature of XPath — you can go to parent, sibling, ancestor elements. CSS cannot do this!

// From an input, find the label above it (parent's previous div)
//input[@id='empId']/parent::div/preceding-sibling::div

// From a label "Employee Id", find the next input
//label[text()='Employee Id']/parent::div/following-sibling::div/input

// (This is exactly the pattern used in your HomePage.java for the empId locator!)

Common axes: parent::, child::, ancestor::, descendant::, following-sibling::, preceding-sibling::, following::, preceding::.

9.6 XPath with index

(//div[@class='oxd-table-card'])[1]   // the 1st matching card
(//input[@placeholder='Type for hints...'])[1]  // from your HomePage.java

9.7 CSS Selectors

CSS selectors are shorter and faster than XPath, but cannot navigate to parent.

PatternMeaningExample

9.8 Quick comparison — XPath vs CSS

XPath
  • Can go to parent / siblings (axes)
  • Match by visible text easily
  • Slightly slower
  • Verbose syntax
CSS Selector
  • Cannot go to parent
  • Cannot match by text
  • Faster, native browser support
  • Shorter syntax
Practical rule Use CSS for simple cases (id, class, attribute). Use XPath when you need to match by visible text or navigate up the tree. Both are fine — pick the one that gives a stable, short locator.
Interview question Q: Why is absolute XPath bad?
Because it depends on the full path. If a developer adds even one extra <div> wrapper anywhere in the parent chain, your locator breaks. Relative XPath uses unique attributes which are far more stable.

10.5 Real example from your ActionDriver.java

Your framework wraps these raw commands inside reusable helper methods. Here is a simplified version of the click + enterText pattern:

public void click(By by) {
    try {
        waitForElementToBeClickable(by);
        driver.findElement(by).click();
        logger.info("Clicked: " + by);
    } catch (Exception e) {
        logger.error("Click failed: " + e.getMessage());
    }
}

public void enterText(By by, String value) {
    waitForElementToBeVisible(by);
    WebElement el = driver.findElement(by);
    el.clear();
    el.sendKeys(value);
}
Why wrap? Because in a real test you call click 100 times. If you wrap it once, you get logging, screenshots, error handling, and waits — for free, everywhere. This is what makes a framework professional.

11. Synchronization — Waits (Critical!)

Modern web pages are not "loaded all at once". They load partially, then JavaScript fills in more later (think: spinning loader, then content appears). If Selenium tries to click a button that hasn't loaded yet → ElementNotFound or NoSuchElement exception.

The fix is to wait for the element to be ready. Selenium gives us 3 wait strategies.

Real-life analogy Imagine you go to a coffee shop. The barista says "1 minute". You have 3 options:
  • Wait exactly 1 minute — even if coffee is ready in 30 seconds, you sit. Wasteful. (= Thread.sleep)
  • Wait until you hear "ready", but max 5 minutes. (= Explicit Wait)
  • Tell the barista "any future order I place, give me 1 min before saying not ready". (= Implicit Wait)

11.1 Thread.sleep() — the wrong way

Thread.sleep(5000);   // pauses 5 seconds, no matter what
  • Pros: simple.
  • Cons: wastes time when page loads fast; fails when page loads slow. Avoid in real tests.

11.2 Implicit Wait — set once, applies always

driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

This tells Selenium: "Whenever I call findElement, if not found immediately, keep retrying for up to 10 seconds." Set once, applies to all findElement calls in the session.

  • Pros: set-and-forget.
  • Cons: only checks "element present in DOM", not "visible" or "clickable". For dynamic UI, not enough.

11.3 Explicit Wait — wait for a specific condition

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));

wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("login")));
wait.until(ExpectedConditions.elementToBeClickable(By.id("login")));
wait.until(ExpectedConditions.titleIs("Dashboard"));
wait.until(ExpectedConditions.urlContains("/home"));
wait.until(ExpectedConditions.alertIsPresent());

This is what your ActionDriver.java uses. Most powerful and recommended.

Common ExpectedConditions

ConditionUse case
presenceOfElementLocatedElement exists in DOM (may be hidden)
visibilityOfElementLocatedElement is in DOM AND visible
elementToBeClickableVisible AND enabled (clickable)
invisibilityOfElementLocatedWait for spinner/loader to disappear
textToBePresentInElementWait for specific text
numberOfElementsToBeWait for table row count
alertIsPresentWait for JS alert popup
frameToBeAvailableAndSwitchToItWait for iframe

11.4 Fluent Wait — advanced

Like Explicit Wait but with custom polling and ignored exceptions.

Wait<WebDriver> wait = new FluentWait<>(driver)
    .withTimeout(Duration.ofSeconds(30))
    .pollingEvery(Duration.ofMillis(500))
    .ignoring(NoSuchElementException.class);

wait.until(driver -> driver.findElement(By.id("result")));
DO NOT mix Implicit + Explicit Wait! If you set both, the actual wait time can become unpredictable (sometimes adds up, sometimes longer). Best practice: use Explicit Wait only. Set Implicit to 0 or skip it.

11.5 Page-load wait (used in your framework!)

driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(60));

This sets the maximum time for driver.get(url) to wait before throwing TimeoutException.

11.6 Wait until JavaScript document is ready (advanced)

wait.until(d -> ((JavascriptExecutor)d)
    .executeScript("return document.readyState").equals("complete"));

Your ActionDriver.waitForPageLoad() method uses exactly this technique.

Interview questions
  1. Difference between Implicit and Explicit Wait? — Implicit is global & only checks presence. Explicit is per-statement & supports many conditions.
  2. What's the default Implicit Wait? — 0 seconds. You must set it explicitly.
  3. Can we set both? — Technically yes, but discouraged due to unpredictable summation behavior in older Selenium. Selenium 4 documents it more clearly but best practice is still: pick one.

12. Dropdowns, Alerts, Frames & Windows

12.1 Dropdowns — the Select class

For HTML <select> dropdowns (the classic ones), Selenium has a built-in helper.

WebElement el = driver.findElement(By.id("country"));
Select dropdown = new Select(el);

dropdown.selectByVisibleText("India");
dropdown.selectByValue("IN");
dropdown.selectByIndex(2);

// All options

    dropdown.deselectAll();
}
Custom dropdowns Many modern apps (React, Angular) use fake dropdowns built from <div> tags. The Select class will not work. You must click them like normal elements: click the dropdown to open, then click the option.

12.2 Alerts — JavaScript popups

JavaScript can show 3 kinds of popups: alert (info OK), confirm (OK/Cancel), prompt (input + OK/Cancel).

Alert alert = driver.switchTo().alert();

alert.accept();              // click OK
alert.dismiss();             // click Cancel
alert.getText();             // read message
alert.sendKeys("hello");     // type into prompt

12.3 iFrames — pages inside pages

An <iframe> embeds another HTML document inside the current page. Selenium cannot "see" elements inside it until you switch to it.

// Switch by index, name/id, or WebElement
driver.switchTo().frame(0);
driver.switchTo().frame("frameName");
driver.switchTo().frame(driver.findElement(By.id("chat-frame")));

// Now interact with elements inside the frame
driver.findElement(By.id("send")).click();

// Switch back to main page
driver.switchTo().defaultContent();
Real-life analogy An iframe is like a picture-in-picture on your TV. By default the remote controls the main TV. To control the small picture, you press a button to "switch focus" to it. switchTo().frame() does exactly that. defaultContent() brings focus back to the main TV.

12.4 Multiple windows / tabs

// Save the current window's id
String mainWindow = driver.getWindowHandle();

// Click a link that opens new tab...
driver.findElement(By.linkText("Open in new tab")).click();

// Get all open windows
Set<String> allWindows = driver.getWindowHandles();
for (String handle : allWindows) {
    if (!handle.equals(mainWindow)) {
        driver.switchTo().window(handle);
        // do work here...
        driver.close();   // close that tab
    }
}

// Return to main
driver.switchTo().window(mainWindow);
Interview question Q: getWindowHandle vs getWindowHandles?
getWindowHandle() returns a single String (the current window). getWindowHandles() returns a Set<String> (all windows). Plural → many.

13. Mouse & Keyboard Actions

For things like hover, right-click, drag-and-drop, double-click, keyboard shortcuts — we use the Actions class.

13.1 Mouse Actions

Actions actions = new Actions(driver);

WebElement menu = driver.findElement(By.id("profile"));
WebElement source = driver.findElement(By.id("src"));
WebElement target = driver.findElement(By.id("dst"));

actions.moveToElement(menu).perform();              // hover
actions.contextClick(menu).perform();               // right-click
actions.doubleClick(menu).perform();                // double-click
actions.dragAndDrop(source, target).perform();      // drag & drop
actions.clickAndHold(source).moveByOffset(50, 0).release().perform();
.perform() is mandatory! The Actions class queues commands. Until you call .perform(), nothing happens. Forgetting .perform() is the #1 newbie bug.

// Combinations: Ctrl+A, Ctrl+C, Ctrl+V

actions.keyDown(Keys.CONTROL).sendKeys("c").keyUp(Keys.CONTROL).perform();
actions.keyDown(Keys.CONTROL).sendKeys("v").keyUp(Keys.CONTROL).perform();

       .pause(Duration.ofMillis(500))
       .click(submenu)
       .sendKeys("hello")
       .build()
       .perform();

13.4 When .click() fails — use Actions

Sometimes a normal element.click() doesn't work because the element is overlapped, animated, or sticky. Try:

Or use JavaScriptExecutor (next module).

14.2 JavaScript Executor — the cheat code

When normal Selenium can't do something (hidden elements, scroll, popup, fancy UI), you can directly run JavaScript in the browser.

JavascriptExecutor js = (JavascriptExecutor) driver;

// Click via JS (bypasses overlays)

// Set value (bypasses sendKeys)
js.executeScript("arguments[0].value='hello';", element);

// Scroll element into view

// Scroll page

js.executeScript("window.scrollTo(0, document.body.scrollHeight);");

// Get page title via JS
String title = (String) js.executeScript("return document.title;");

// Highlight an element with red border
js.executeScript("arguments[0].style.border='3px solid red'", element);

15. TestNG — Running Tests Like a Pro

So far, our main method runs only one scenario top to bottom. In real projects we have hundreds of tests — we need a proper test framework. That's TestNG.

Real-life analogy TestNG is the school exam supervisor. It decides:
  • Which question paper to give (which test classes to run)
  • The order (test order / priority)
  • Pass / Fail rules (assertions)
  • Setup before exam (open hall, distribute papers = @BeforeMethod)
  • Cleanup after exam (collect papers, lock hall = @AfterMethod)
  • Final result sheet (HTML report)

15.1 Annotations (the heart of TestNG)

@BeforeTestBefore all <test> tags in xml

@BeforeMethodBefore each @Test
@TestThe actual test
@AfterMethodAfter each @Test

15.3 Sample test class

    @Test(priority = 1, description = "Verify valid login")
    public void validLoginTest() {

15.4 Assertions

An assertion = a check. If it fails, the test is marked FAIL.

  • Hard Assert — Assert.assertEquals(actual, expected) — if it fails, the rest of the test stops.
  • Soft Assert — SoftAssert sa = new SoftAssert(); — collects all failures, you call sa.assertAll() at the end.
Assert.assertEquals(actual, expected);
Assert.assertNotEquals(actual, expected);
Assert.assertTrue(condition);
Assert.assertFalse(condition);
Assert.assertNotNull(object);
Assert.fail("forced fail with message");

15.8 RetryAnalyzer — flaky test recovery

Sometimes a test fails due to network/timing issues, not a real bug. IRetryAnalyzer retries a failed test N times before declaring fail. Your repo's RetryAnalyzer.java implements this.

15.9 Parallel Execution

Run multiple tests at the same time on different browser windows.

<suite name="S" parallel="methods" thread-count="3">

Important: WebDriver is not thread-safe. Use ThreadLocal<WebDriver> — just like your BaseClass already does! That's the entire reason for the ThreadLocal wrappers in your BaseClass.java.

Interview question Q: How do you achieve parallel execution in Selenium?
Two parts: (1) tell TestNG to run in parallel via parallel="methods"/"classes"/"tests"; (2) make WebDriver thread-safe using ThreadLocal<WebDriver>. Without ThreadLocal, threads share the same driver and tests crash.

16. Page Object Model (POM) — The Right Way to Organize

Imagine you have 20 tests. All of them need to login. So you copy-paste the login code (findElement(username)... password... click...) into all 20 tests.

One day the developer changes the username field's name attribute. Now you must edit 20 tests. Painful and error-prone.

Solution: Page Object Model. Each web page becomes a Java class. The class holds the locators and the actions. Tests just use the page class.

Real-life analogy Think of a TV remote. The TV has many buttons inside but the user just presses "Volume +", "Channel Up". The complexity is hidden inside the remote. Page Object = the remote. Test code = the user. The user doesn't care how the remote works internally — just presses buttons.

16.1 Folder structure (your repo)

src/main/java/com/orangehrm/ actiondriver/ ActionDriver.java <- common element-action helpers base/ BaseClass.java <- driver setup/teardown listeners/ TestListener.java <- TestNG event hooks pages/ LoginPage.java <- one class per page HomePage.java utilities/ ExcelReaderUtility, DBConnection, ApiUtility, ExtentManager, LoggerManager, DataProviders, RetryAnalyzer src/main/resources/ config.properties, log4j2.xml src/test/java/com/orangeHRM/test/ LoginPageTest.java, HomePageTest.java, ...

16.2 A Page Class (your LoginPage.java simplified)

public class LoginPage {
    private ActionDriver actionDriver;

    // 1. Locators - private!
    private By userNameField = By.name("username");
    private By passwordField = By.name("password");
    private By loginButton   = By.xpath("//button[@type='submit']");
    private By errorMessage  = By.xpath("//p[text()='Invalid credentials']");

    // 2. Constructor - get the action driver
    public LoginPage(WebDriver driver) {
        this.actionDriver = BaseClass.getActionDriver();
    }

    // 3. Actions - public methods exposing what users can do
    public void login(String u, String p) {
        actionDriver.enterText(userNameField, u);
        actionDriver.enterText(passwordField, p);
        actionDriver.click(loginButton);
    }

    public boolean isErrorMessageDisplayed() {
        return actionDriver.isDisplayed(errorMessage);
    }
}

16.3 A Test using the Page Class

public class LoginPageTest extends BaseClass {
    @Test
    public void validLoginTest() {
        LoginPage login = new LoginPage(getDriver());
        login.login("Admin", "admin123");

        HomePage home = new HomePage(getDriver());
        Assert.assertTrue(home.verifyOrangeHRMLogo());
    }
}

Notice: the test code reads almost like English. "Login. Verify logo." No locators, no findElement. That's the beauty of POM.

16.4 Benefits

  • Reusable — 20 tests can call login(u, p).
  • Maintainable — if locator changes, edit ONE place.
  • Readable — tests describe scenarios, not how-to clicks.
  • Layered — tests → page → action driver → selenium.

16.5 PageFactory (alternative POM style)

Selenium ships a helper called PageFactory that uses @FindBy annotations instead of By objects.

public class LoginPage {
    @FindBy(name="username")  WebElement userField;
    @FindBy(name="password")  WebElement passField;
    @FindBy(xpath="//button[@type='submit']") WebElement loginBtn;

    public LoginPage(WebDriver driver) {
        PageFactory.initElements(driver, this);
    }

    public void login(String u, String p) {
        userField.sendKeys(u);
        passField.sendKeys(p);
        loginBtn.click();
    }
}
By vs PageFactory Both are valid. Industry trend leans toward By + WebDriverWait (your repo's pattern) because PageFactory has subtle issues with stale elements in dynamic pages and lazy loading. The By approach is more explicit and reliable.

<Configuration>

22. API Testing Basics (Rest Assured)

UI tests are slow and fragile. Many bugs are at the API level — before the UI is even drawn. API tests are 10x faster and more stable.

22.1 What is an API?

An API (Application Programming Interface) is how two applications talk. For web apps, it's almost always HTTP + JSON. The frontend asks the backend "give me user 5", the backend replies with JSON.

Real-life analogy API = the waiter at a restaurant. You (frontend) say "1 dosa please." The waiter (API) goes to the kitchen (backend), comes back with the dosa. You don't need to know how the chef cooks — you just talk to the waiter.

22.2 HTTP methods

MethodPurposeExample
GETRead dataGET /users/5
POSTCreate newPOST /users
PUTUpdate existing (full)PUT /users/5
PATCHUpdate existing (partial)PATCH /users/5
DELETERemoveDELETE /users/5

22.3 Status codes (the response number)

  • 2xx — Success (200 OK, 201 Created, 204 No Content)
  • 3xx — Redirects
  • 4xx — Client error (400 Bad Request, 401 Unauthorized, 404 Not Found)
  • 5xx — Server error (500 Internal, 502 Bad Gateway, 503 Service Unavailable)

22.4 Rest Assured example

import static io.restassured.RestAssured.*;
import static org.hamcrest.Matchers.*;

@Test
public void getUserTest() {
    given()
        .baseUri("https://reqres.in/api")
        .header("Accept", "application/json")
    .when()
        .get("/users/2")
    .then()
        .statusCode(200)
        .body("data.id", equalTo(2))
        .body("data.email", containsString("@reqres.in"));
}

That's the given-when-then pattern: given these conditions, when I make this call, then I expect this response.

22.5 Why mix UI + API tests?

  • Use API to set up data quickly: create a user via API, then test login on UI.
  • Use API to verify after a UI action: click "Save", then call GET to confirm DB has the value.
  • This makes tests faster, less flaky, and more focused.

24. Best Practices (Industry Standards)

24.1 Locator strategy

  • Prefer id > name > CSS > XPath.
  • Avoid auto-generated locators (e.g., id="mat-input-127" — the number changes every render).
  • Ask developers to add data-test-id="loginBtn" attributes — stable, dedicated for tests.

24.2 Waits

  • NO Thread.sleep() in production code.
  • NO mixing implicit + explicit waits.
  • Use WebDriverWait with ExpectedConditions.

24.3 Test structure (AAA)

  • Arrange — set up data, navigate to page
  • Act — perform the user action
  • Assert — verify the outcome

24.4 One assertion per test (ideally)

Each test should validate one behavior. Easier to debug when it fails. Long tests with 10 asserts hide what truly broke.

24.5 Independent tests

Test 2 should never depend on Test 1 to pass. Each test must set up its own data and not rely on previous tests. Otherwise parallel execution is impossible.

24.6 Avoid hardcoding

Don't put URLs, credentials, file paths in code. Use config.properties, environment variables, or vault for secrets.

24.7 Logging + reports

Every action should log what it did. Every failure should capture a screenshot. Without these, debugging is impossible.

24.8 Page Object Model

Always. No locators in test classes.

24.9 Driver lifecycle

One driver per test method (@BeforeMethod / @AfterMethod) — clean state, easy parallelization, no leaks.

24.10 Don't ignore flaky tests

If a test fails 1 in 5 runs, it's not "flaky luck" — it's a real timing/data issue. Fix the root cause. Retries (RetryAnalyzer) are a band-aid, not a cure.

A great framework checklist
  • Cross-browser config in properties
  • Page Object Model
  • Reusable action driver layer
  • Explicit waits everywhere
  • Log4j logs to file
  • ExtentReport with screenshots on failure
  • Data-driven via Excel/CSV
  • Parallel execution with ThreadLocal
  • Retry analyzer for transient failures
  • CI integration (GitHub Actions / Jenkins)

25. Interview Q&A — The Top 30

1. What is Selenium WebDriver? An open-source library for automating web browsers. It controls the browser via the browser's native automation API and supports multiple languages.
2. Difference between driver.close() and driver.quit()? close() closes the current window. quit() closes all windows and ends the WebDriver session, releasing the chromedriver process.
3. Difference between findElement and findElements? findElement returns the first match or throws NoSuchElementException. findElements returns a List (empty if none, no exception).
4. What are the types of locators? id, name, className, tagName, linkText, partialLinkText, cssSelector, xpath. (Total 8.)
5. XPath types? Absolute (starts with /) and Relative (starts with //). Always prefer Relative.
6. CSS vs XPath, which is better? CSS is faster and shorter. XPath is more powerful (text matching, parent traversal). Use CSS when possible, XPath when necessary.
7. Difference between Implicit and Explicit Wait? Implicit: global timeout for findElement, only checks DOM presence. Explicit: targeted wait for a specific condition (visible, clickable, etc.) on a specific element.
8. What is FluentWait? A flexible explicit wait with custom polling interval and ignored exceptions. Inherits from WebDriverWait's base class.
9. How do you handle alerts? driver.switchTo().alert().accept()/dismiss()/getText()/sendKeys(...).
10. How to handle frames? driver.switchTo().frame(index/name/element); switch back with defaultContent() or parentFrame().
11. How to handle multiple windows? Save current handle with getWindowHandle(), iterate through getWindowHandles(), switch with switchTo().window(handle).
12. How to handle dropdowns? For <select> tags use the Select class with selectByVisibleText/Value/Index. For custom dropdowns, click and select like normal elements.
13. How to perform mouse hover? new Actions(driver).moveToElement(element).perform();
14. How to take screenshot? ((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE) then copy via FileUtils.
15. What is Page Object Model? A design pattern: each web page is a Java class containing locators + methods (actions). Tests use page methods, not raw locators. Reusable + maintainable.
16. Difference between POM and PageFactory? POM is the pattern. PageFactory is one Selenium implementation using @FindBy annotations. POM with By objects is the other implementation.
17. What is TestNG? A test framework inspired by JUnit. Provides annotations, asserts, parallel execution, dataproviders, listeners, configurable test runs via testng.xml.
18. Difference between @BeforeTest and @BeforeMethod? @BeforeTest runs once per <test> tag in testng.xml. @BeforeMethod runs before EACH @Test method.
19. Hard vs Soft Assert? Hard: stops on first failure. Soft: collects all, you call assertAll() at end to report.
20. How to run tests in parallel? In testng.xml: parallel="methods/classes/tests" with thread-count. Use ThreadLocal<WebDriver> to keep drivers thread-safe.
21. What is ThreadLocal and why? ThreadLocal stores a separate value per thread. WebDriver isn't thread-safe, so each thread needs its own driver instance — ThreadLocal isolates them.
22. What is JavaScriptExecutor? Interface to run raw JS in the browser. Used when normal Selenium fails: clicks blocked by overlays, scroll, hidden elements.
23. How to scroll a page? js.executeScript("window.scrollBy(0,500);"); or scrollIntoView(true) on an element.
24. StaleElementReferenceException — why? The element you found earlier was destroyed/replaced by the page's JS. Re-find it before using.
25. ElementClickInterceptedException? Another element is on top of yours (modal, banner). Solutions: scroll into view, wait for the overlay, click via JS.
26. How do you handle CAPTCHA / OTP? Selenium can't. Strategies: ask developers for a test bypass, mock the OTP service, disable captcha in test env, or use a known dummy code.
27. How is data passed to a test? Via @Parameters from testng.xml, or @DataProvider from a Java method (often reading Excel/CSV/JSON).
28. What is a Listener in TestNG? A class implementing ITestListener (or others). Hooks into events (onTestStart, onTestSuccess, onTestFailure, onFinish) to perform actions like screenshots and reporting.
29. Headless browser execution? Run browser without GUI — faster, ideal for CI. options.addArguments("--headless=new") for Chrome.
30. How would you design a Selenium framework from scratch?
  1. Maven project with selenium, testng, log4j2, extentreports, poi.
  2. BaseClass with ThreadLocal driver setup/teardown.
  3. ActionDriver wrapper for click/sendKeys with waits + logs + screenshots.
  4. Page classes (POM) per screen.
  5. Test classes extending BaseClass.
  6. config.properties + log4j2.xml for config.
  7. TestNG XML + DataProviders for data-driven runs.
  8. TestListener & ExtentManager for reports.
  9. RetryAnalyzer for flaky tests.
  10. GitHub Actions / Jenkins for CI.
